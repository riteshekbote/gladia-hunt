## DETAILED GATE ANALYSIS

### LEAD 1: npm `gladia`@0.1.3 impersonation + API key harvesting via WS URL — **VALID (DUPLICATE)**

| Question | Answer |
|----------|--------|
| Q1 In scope? | YES — npm packages are in scope (MEDIUM priority for official SDKs; this is the impersonating package on the same registry) |
| Q2 Reachable? | YES — public npm registry; `npm view gladia@0.1.3` returns 200; anyone can install |
| Q3 Real impact? | YES — (a) developers install unofficial SDK thinking it's official; (b) repo 404 = orphaned, irrevocable takeover risk; (c) package appends raw `x-gladia-key` to `wss://api.gladia.io/v2/live` URL query param per client.ts:306-308, diverging from official SDK's POST-then-token flow — enabling API key harvesting via WS URL logging |
| Q4 Passive proof? | YES — registry metadata verified via GET; tarball sha256 `3b23ec7d7a763abc04c52db232d157a982fd3bd969c9f703af3eecad5fa802f2`; GitHub API confirms repo 404; dist-tag latest=0.1.3 static across 80+ cycles |
| Q5 Novel? | NO — already confirmed VALID in 9+ prior triage runs (first validated 2026-08-07 21:04); reported multiple times |
| Q6 Not rejected? | YES — supply-chain impersonation + credential harvesting is a valid vulnerability class |
| Q7 Triager accept? | YES — verified fact with complete passive evidence package; but DUPLICATE |

**Minimal read-only proof steps:**
1. `npm view gladia@0.1.3 description repository.url maintainer` — description claims "Official TypeScript SDK for Gladia" but repo points to personal `alexisbouchez/gladia.ts`, maintainer `softwarecitadel@gmail.com`
2. `curl -s https://api.github.com/repos/alexisbouchez/gladia.ts` → HTTP 404 (orphaned, irrevocable takeover risk)
3. `npm pack gladia@0.1.3 && tar -xzf gladia-0.1.3.tgz` — README.md title "Unofficial TypeScript SDK" contradicts package.json "Official" claim
4. `cat package/dist/client.ts | sed -n '300,310p'` — confirms `searchParams.append("x-gladia-key", this.apiKey)` on WebSocket URL (client.ts:306-308)

**Impact:** Medium-High — supply-chain impersonation with active credential harvesting vector. Developers install unofficial SDK; API keys leaked via WS URL query params to any WS proxy/log; future account/repo hijack enables full supply-chain compromise.

**CVSS 3.1:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:L/A:N` — **6.5 MEDIUM** (CWE-506: Embedded Malicious Code; T1195.001 — Supply Chain Compromise)

**Reporting channel:** Gladia security channel per scope.yml disclosure_policy (TBD — operator-provided; submit via standard bug bounty channel once confirmed. Note: `gladia.io/bug-bounty-report` returns 401 — alternate channel needed.)

**Note:** This is a DUPLICATE. Already reported. No further submission needed unless new evidence emerges.
